# Latest decision: pale cards on a warm-white Collect canvas

The card-versus-column colour question was evaluated in the browser, not adopted automatically. Both materials were compared on the same populated and stress boards, in both scripts/themes, on phone and desktop. Pale card colour wins for individual contribution identity and less enclosing apparatus; the previous version wins for a continuous category region and quiet neutral reading surfaces. Full-strength card fills were too insistent on long notes, so the implemented fills are paler. Category labels, alignment and the named picker retain organisation; colour does not imply ownership or selection. Only Collect changes material. The complete rationale, limitations and evidence are in [CARD-COLOUR-REVIEW.md](CARD-COLOUR-REVIEW.md). Earlier entries below are retained as iteration history.

# Current refinement — separate contributions, restrained colour

The latest user feedback supersedes the initial ruled-row visual consolidation below. The user wants each note to stand alone, dislikes the saturated blue, and explicitly prefers Neo’s Join composition. The candidate now uses individual note cards in unboxed category lanes, distinct theme/topic/action cards, a neutral selected agenda item, and ink/orange/neutral colours. Voting uses a card grid with an evidence preview, a separate inspection disclosure and a distinct vote button. Summary records remain discrete cards rather than an article-like list.

Join uses facilitator → title → joined/stage context → name → short privacy hint → Join, with further anonymity detail in a disclosure. It does not infer presence from joined membership. The stack is limited to four initials and accompanied by a real count. Invite is absent from entry screens.

Phone Group previously opened with a long list of themes, hiding the note-selection task. It now opens on Notes and offers a Notes/Themes switch; selection survives switching. Desktop shows a two-column note-card pool beside theme cards. A category filter and membership labels help orient selection; the selection dock appears only when there is a selection. No dragging is required. Source preservation, permissions, voting order, closure history and draft behaviour are unchanged.

These are changes to the existing final candidate, not another design direction. `qa/refined-*.png` and `qa/refinement-results.json` are the current visual evidence; earlier screenshots document the preceding iteration.

# Taqyeem — final candidate decisions

## Evidence reconciliation and rules (before implementation)
ROUND3 and REVIEW prioritise Editorial’s originality and density. The independent Codex evaluation prioritises Neo’s bilingual subject/evidence/action composition. Neither is a universal score: they inspected different snapshots. Current Neo already uses denser ruled notes and a single active composer; keep those refinements. Its source still replaces the root on updates, reseeds on role changes, counts navigation as discussion, fabricates voter counts and drops pending proposals on closure. These findings still apply. Browser inspection of Studio, Editorial, Neo and After Hours confirms the different working compositions; originals are retained in qa/original-*.png. The first three concepts were reviewed through their source and the existing comparisons, without rescoring.

Use Neo typography and material, Studio entry/composer order and explicit allowance, Editorial structural rules and unmistakable selection, After Hours phone economy. Remove stage fader, shape identities and floating desktop console. Orange identifies the next shared step; blue with a check identifies selection; ownership uses explicit text. This is a meaningful departure from Neo’s hardware apparatus, not a palette collage.

## Conservative command rules
- Collect-only note creation/edit/delete; only the author can edit, including anonymous notes. After Collect, drafts remain available but submission is locked. Anonymous hides attribution on the board, not from a hypothetical server; prototype store contains author IDs.
- A note belongs to at most one theme. Group-only facilitator commands rename, add/remove membership and dissolve themes without deleting original evidence. Ungrouped notes remain eligible topics. Skipping Group is allowed. No regrouping once ballot opens.
- One vote per topic/member; configurable allowance, default five. Fewer votes are valid. Ready is a separate reversible declaration, never inferred from authors or votes. Ballot order is stable; totals hidden until closure. Ties follow original topic order. Delayed commands revalidate on commit: closing first rejects in-flight votes. Reopening preserves votes; no regrouping option.
- Topic browsing is private for either role. Only explicit facilitator Live topic changes shared focus. Only explicit Mark discussed / Skip changes outcome. Outcomes are discussed, skipped or unaddressed; a separate decision may say no action required.
- Participants suggest; facilitator additions are agreed. Suggested/agreed/deferred/declined are proposal dispositions. Only agreed actions have open/completed execution. Closure retains every proposal. Owner or facilitator may update completion after closure; historical snapshot remains unchanged.
- Empty stages always have a facilitator forward path. Normal progression never seeds or replaces contributions.

## State, invitation and Lab contract
Per-board localStorage is shared across same-origin tabs. sessionStorage holds each tab’s identity, drafts and private navigation. Invitation `?board=ID&join=1` opens that board’s Join screen. No cross-device persistence; clearing browser storage removes data. Unknown IDs are invalid. Returning identity is a per-tab convenience, not authentication. Reviewer tools expose seeded review/stress/empty boards, role, stage and connection/error conditions. These are expressly simulations. Lab messages change language/theme/role without resetting content; step messages navigate entry screens or explicitly inspect shared stage as reviewer tooling. There is no legacy Studio.S compatibility: `window.Final` provides the candidate store/commands, documented in qa. Original seven retain their existing contract.

## Privacy and continuity
No named non-contributor lists. Joined count says nothing about presence. Ready is opt-in and aggregate. Failed/slow operations preserve editor fields; double submit is disabled; draft dismissal keeps work, explicit Discard removes it. External updates rerender only the main view, never the open dialog. Interface preference changes update labels in place inside an editor. User content is never translated. No production security or transport claim is made.

## Consolidation after rendered review
The final phone discussion is intentionally a different composition, not a scaled desktop grid: remove repeated stage/header apparatus, open on the topic at roughly y133 in the checked 390px English state, then two notes, explicit full-evidence disclosure and related actions. Its full-title agenda is a native modal. The dock owns phone action capture, removing the repeated button in related actions; stage advance stays separate. Desktop navigation is normal flow with a bounded, keyboard-scrollable agenda after the original sticky dock overlapped outcome controls. Eight-category boards use selected shelves of three lanes; the complete named picker selects every shelf. The working board keeps its identity through strong ruled category headings, direct voices and blue selection, rather than participant tokens or hardware decoration.

Independent verification found and corrected detached focus restoration twice (dismissal after unrelated render, then success after rerender), low field boundary contrast, and hidden print evidence. Print opens evidence disclosures and includes a print-specific content-visibility rule. Copy awaits successful completion; failures are honest. Drafts are scoped by board within each viewer tab; reviewer fixture reset explicitly clears that fixture’s drafts after confirmation. No original concept was changed during these refinements.

## Follow-up: soft colour for category columns
The user requested light column colours such as cyan and orange after the card refinement. Collect now gives each category a muted backdrop, while retaining separate neutral note cards. Mint, peach, cyan and lilac provide context without returning the saturated blue action/selection surfaces the user rejected. Colour assignment follows stable category order, never language, stage or shelf position. Labels remain explicit; colour is not a permission or state signal. Dark mode uses restrained tinted surfaces. This supersedes only the transparent-lane appearance described above.

## Actions alignment and empty-view refinement
The filter label's surrounding margins and the toolbar's alignment previously left Add action offset from the select. Both now use explicit 48px controls on the same baseline; the label lives in its own field wrapper. The oversized sentence heading and detached explanatory copy become a compact Actions heading, clear supporting text and actual proposal counts. Counts in filter options make empty views predictable. No-match states identify the selected disposition and offer a reset to All; no records are changed or removed. Filter changes retain keyboard focus, and the separate action editor remains mounted during updates. Equal-height card rows align their action footers without changing ownership or proposal permissions.

## Remove oversized collection dock
The user questioned the oversized black bar and “I’m ready” button. The bar had inflated a secondary meeting signal into a competing primary action. It is removed from Collect. Keep one Add note button in the desktop sticky toolbar and one compact, labelled reachable phone control (the same DOM button, responsive positioning). Replace Collect’s “I’m ready” with a quiet “Done writing” toggle. This is voluntary self-report to help the facilitator without inferring participation from note authors. It is reversible, does not submit text, does not lock further writing and cannot advance the meeting. Voting retains its separate readiness signal; command rules are unchanged.

## Consistent feedback identity and clearer first/fourth colours
The user correctly questioned losing the card-colour concept after Collect. This supersedes the earlier decision to keep original feedback neutral in later stages. Every original contribution now carries its own category tone into grouping, ballots, discussion evidence and summary evidence, including modal inspection and Home's specimen. Group selection does not replace the category fill: ink border/check/pressed state carries selection. Unmixed single-note ballot cards retain the same colour; mixed-category themes and actions use neutral surfaces and preserve all source colours inside evidence inspection. A shared warm-white light-board canvas makes the working stages cohesive while preserving the preferred Neo entry composition.

The old mint and lilac were too close to off-white. Increase green/purple chroma modestly and separate their hues, rather than saturating every card or changing the meaning of categories. Four-colour overview screenshots include a reviewer-only Shout-outs contribution so the fourth colour is visible beside the first; no original fixture asset or user board was changed to make that evidence.

## Landing reflects the shared note language
The earlier two-note specimen did not fully communicate the four-category note style. Home now uses a four-note wall (green, peach, cyan and lavender) plus a neutral agreed-action example, on the same warm-white canvas. Existing note typography, shapes and category-tone tokens are shared, rather than inventing a separate marketing card style. Upright cards, honest metadata and mixed-script example content reflect the real board; no decorative paper folds, rotation, tape or invented social proof was added. Create/Join retain their separate entry layouts; no board state or editor behaviour changes.
